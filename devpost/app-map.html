Job Hunter AI

A five-step Streamlit proof of concept that turns a reviewed CV profile and remote-job preferences into evidence-based job assessments. Skills match and eligibility remain independent so a technically relevant job is never presented as applicable without supporting eligibility evidence.

Main pieces

  • Guided UI: five page scripts in app_pages/, registered by streamlit_app.py.
  • Private CV path: local PDF text extraction in job_hunter/cv/pdf.py, structured provider extraction in job_hunter/inference/client.py, and session invalidation in job_hunter/session.py.
  • Bounded agent path: tool planning and source orchestration in job_hunter/agent/, using only Remotive and the configured Greenhouse boards.
  • Evidence decisions: deterministic skills, experience, eligibility, and ranking logic in job_hunter/analysis/.
  • Repeatable demo path: public job snapshots loaded by job_hunter/snapshots/loader.py, always labeled with their date and non-live status.

Reference route: three useful stops

This route was generated from the finished source and is not presented as a completed live code tour.

  1. Input and privacy boundary. Open app_pages/upload_cv.py and search for Analyze CV. The button calls local PDF extraction and then HFGateway.extract_profile only after the disclosure and consent gate.
  2. Agent and decision boundary. Open job_hunter/agent/orchestrator.py and search for run_pipeline, then open job_hunter/analysis/eligibility.py at evaluate_eligibility. The orchestrator collects evidence; deterministic code owns the final eligibility label.
  3. Visible evidence. Open app_pages/results.py and search for Evidence-Based Job Matches. This page keeps skills match and eligibility separate and exposes restrictions, unknowns, freshness, attribution, and original links.

To change this, start here

  • CV file acceptance or readable-text rules: job_hunter/cv/pdf.py → extract_pdf_text.
  • Structured CV or job extraction prompts and provider error mapping: job_hunter/inference/client.py → HFGateway.
  • Allowed Greenhouse boards and provider configuration: job_hunter/config.py → GREENHOUSE_BOARDS and settings.
  • Eligibility evidence and conservative labels: job_hunter/analysis/eligibility.py → evaluate_eligibility, with regression coverage in tests/unit/test_rules.py and tests/unit/test_final_fixes.py.
  • Result-card wording and filters: app_pages/results.py.

A practice to reuse

Keep probabilistic extraction separate from deterministic decisions. The approved principle in devpost/prd.md says a strong skills match does not establish eligibility. The provider extracts grounded job facts, while evaluate_eligibility applies explicit rules and preserves unknowns. The regression test_strong_skill_match_cannot_override_location_conflict proves that boundary. On another agent project, use the same pattern: let the model structure ambiguous text, validate its schema and evidence, then reserve consequential labels for small, testable rules whenever the policy can be expressed deterministically.
