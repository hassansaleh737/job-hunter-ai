# Job Hunter AI — Evidence-Based Job Matching

A privacy-conscious, five-step Streamlit proof of concept: **Upload CV → Review Profile → Preferences → Find Jobs → Results**.

- Real tools: Remotive public jobs API and four approved Greenhouse public company boards.
- Hugging Face `InferenceClient`: tested model configuration `Qwen/Qwen3.5-9B` / `deepinfra`.
- LLM plans tool calls and extracts stated job requirements; **Python deterministic rules** decide `Eligible`, `Unknown`, `Not Eligible`, and `Strong` / `Partial` / `Weak` skills match independently.
- CV is accepted as a text-based PDF only, extracted in memory, never saved to an app database or repository. The extracted **text** is sent to Hugging Face/DeepInfra only after a visible disclosure and opt-in.
- Local PoC; no login, job application submission, or background monitoring.

## Run on Windows (PowerShell)

1. Install **Python 3.12** and [uv](https://docs.astral.sh/uv/getting-started/installation/).
2. Create a local `.env` file that contains:

```env
HF_TOKEN=YOUR_PRIVATE_HF_TOKEN
HF_MODEL=Qwen/Qwen3.5-9B
HF_PROVIDER=deepinfra
```

3. Run from the project root:

```powershell
uv sync
uv run pytest
uv run streamlit run streamlit_app.py
```

Then open the local URL printed in the terminal, usually http://localhost:8501.

**Alternative if uv isn't installed:** create a Python 3.12 venv and install the libraries from `pyproject.toml` using `pip install -e .` (the uv method is preferred). The `uv.lock` file will be generated by `uv sync` on the connected local machine.

## Create a genuine, dated demo snapshot

```powershell
uv run python scripts/collect_snapshot.py
```

To pre-extract public job facts once (no CV data used), then start the demo:

```powershell
uv run python scripts/prepare_demo.py
uv run streamlit run streamlit_app.py
```

The snapshot collector pulls real postings only; snapshots are always labeled **Dated Snapshot — NOT Live**. The repository ignores locally generated `demo.json` and `demo_requirements.json` to avoid unintentionally republishing collected job text. A reviewer can regenerate them with these commands. Remotive recommends limited fetch frequency; do not recollect unnecessarily.

## Architecture

`streamlit_app.py` + five `app_pages/`, Pydantic domain models, PyMuPDF CV extraction, Hugging Face inference gateway, bounded agent search orchestration, Remotive/Greenhouse source adapters, deterministic rules, session-local job state, and pytest unit/integration tests.

## Privacy & security

- **Never commit `.env` or CVs**. `.gitignore` excludes both. Run `git check-ignore .env` to check protection.
- CV PDF bytes are read into memory only. User must consent before **extracted text** is transmitted externally. No personal data is serialized to snapshots.
- Hugging Face/DeepInfra provider-side policies are separate from the app's session-only storage. Review them before using a personal CV.
- The session does not persist between app visits. Replacing a CV invalidates prior profile-dependent analysis and results.
- Error messages are intentionally generic so external errors cannot leak CV content or secrets.
- Job URLs are displayed from the original public source; external data is untrusted.

## Known honest limitations

- Hugging Face structured-output and tool-calling smoke checks passed with synthetic data on October 26, 2026 using `Qwen/Qwen3.5-9B` through `deepinfra`. Live source availability can still change and should be checked before the demo.
- The original source supplies location and work-authorization evidence inconsistently; ambiguous cases correctly remain `Unknown` rather than being marked eligible.
- The UI is designed for short demo runs; live inference cost and latency depend on the HF account/provider and how many jobs are shortlisted (max 6). Live inference uses a bounded per-call network timeout; cancellation cannot interrupt an already executing network call.
- Remotive network requests are cached for six hours per app process; this avoids repeated calls but cannot enforce a global per-day API quota across app restarts.
- An in-flight provider/HTTP call may continue after the user presses Cancel; its results are discarded and a second run is blocked within the same Streamlit session until that worker stops.
- Skill evidence from descriptions uses exact, boundary-aware mentions; the application cannot establish proficiency or verify the truth of CV claims. Documented experience is used conservatively and never added across overlapping roles; missing experience in a CV is `Unknown`, not automatic ineligibility.
- Automated UI end-to-end coverage remains limited. Run the full manual 5-page flow with both Live Search and Dated Snapshot before submitting.
